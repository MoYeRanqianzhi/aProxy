# Command-line language: inventory and ruled design

Baseline: `390cb492`, both build variants and platform branches. Select the language at the sink, not by filtering rendered text. The 0.2.0 machine documents have shipped only in pre-releases: normalize all authored sentences to English now. Preserve fields, types, codes, details, exits, streams and line order; keep the version line, the frozen force contract and any text *parsed* by a released executable byte-for-byte. Record such parsed exceptions separately.

## 1. What produces text

The two inventories below have different units. Appendix A counts **source occurrences by file**: an authored literal (including byte/raw literals), or one group of derive doc lines. It counts both conditional arms, repeated occurrences separately, and excludes tests, ordinary comments, examples and build-time output. A format string is one site, not one per line/argument. Each site has one *primary* lane; a shared origin is counted at its most restrictive sink. B is deliberately a complete fixed-vocabulary account, including code tokens, parser spellings, literal data, separators and private non-prose, not a claim that all those literals are English sentences or even emitted. The site count is **not** the number of translations to write. The second inventory below counts **boundary representations (D)**, including those without any string literal at the write site (e.g. `serde_json::to_writer(file, &e)`). D overlaps the lexical columns; do not add it to their sum.

| Lane | Reader and policy |
|---|---|
| A | A person: command output, errors, repair instructions, prompts, launch dialogs, help including help for hidden commands. Route prose through a typed bilingual definition. Preserve stdout/stderr, line boundaries, quoting, redaction, command examples, severity/code tokens and data. Human-only English that exists today also needs a Chinese rendering. |
| B | Programs, agents or implementation: fixed, never consult language. Includes IO/serde keys and enum spellings; JSON/TOML values printed by `get`, raw reports, English diagnostics and summaries, command/flag/alias names, paths, URLs, environment names, redaction markers, version, protocol bytes, generated entry and login scripts, skill documents and `show --files`. Data supplied by a user, OS, upstream or external worker is not aProxy prose; it need not be ASCII. |
| C | A Chinese producer on a fixed or shared path; the indexed exceptions and their readers are in Appendix B. Some are only internal invariant messages. Do not assume that localizing a caller is safe just because the original literal is Chinese. |
| D | A sentence leaves its producer; the receiver, not the writer, selects the presentation. Table in §4 identifies writers, readers, codes/parameters, additions or no change. |
| E | Diagnostic records: instance logs, startup.log, watchdog.log, tracing on foreground console/CLI stderr, captured worker stderr and returned excerpts. Fixed English for all existing and future authored log prose. |
| F | C1–C8: `aproxy-ipc/src/home.rs`, `aproxy-ipc/src/ledger.rs`, `src/install/force.rs` plus the entire `tests/force_contract.rs` (test, not a shipping producer). Do not edit, including strings, tests, layouts or streams. Protected callers also include `VERSION_LINE`, sole-flag fast path, and the force wrapper's exit/step/locking order. |

**Machine command count.** `src/commands/mod.rs:50` distinguishes **20 canonical JSON modes** (aliases are not extra producers): `start`, `status`, `find`, `doctor` (4); `stop`, `restart`, `restore` (3); `alias list` (1); `config` and `settings` each `show/get/set/unset` (8); `install --check` and installing event stream (2); `skill install/list` (2). Early `home_invalid`/invalid settings, `finish_json`, `Results.failed` and the skill-install failure document are separate error *paths*, not extra modes. `install --abort/--force/--continue/--skills-only` conflict with `--json`. Use all 20, as well as the non-JSON modes, when checking unchanged stdout, stderr and exits. Do not assume every error uses the code table's English summary.

**Log decision (E).** Instance traces are largely Chinese with structured English fields; watchdog.log already has English event templates, but interpolates a Chinese respawn reason. Startup.log includes the detached child's config/bind/format failures, non-loopback warning, job-object and slow-retry notices. `src/commands/logs.rs:80,201` sends its own path/connection/truncation/end messages to stderr; stdout is a tail (including its existing lossy line decoding) or follow bytes. Keep that split and the existing tail/follow semantics. Do not translate old files on read. Fixed English new records cost Chinese users untranslated forensic detail but permit grep, piping, mixed-version logs, and language changes between writing and reading. Translating on write strands future readers in the starter's language; translating on read needs an event schema for every old/free-form/third-party line and changes pipelines. Neither is recommended. The same rule applies to diagnostic tracing when temporarily enabled on the CLI, **not** to ordinary human stderr. New startup excerpts embedded in JSON are English too.

## 2. Message definitions and dependencies

Put `Lang::{En,Zh}`, the process `OnceLock<Lang>`, explicit `Lang` selection, system lookup and the declarative macro in `aproxy-ipc/src/i18n/`; its own per-area modules cover client, registry and diagnostics. Both binaries **already depend on** aproxy-ipc; aproxy-format already enables `config-file` and `body-inspection`. No new crate, optional translation dependency, link back to aproxy, runtime catalog, feature-unifying client dependency or source file shared by relative path across published packages. Add only `Win32_Globalization` on the existing Windows-only windows-sys 0.52 edge. Keep the exact `featureless_tree_stays_small` closure. Keep CLI, instance, diagnostics, install/download, skill and help definitions near their owners (`src/i18n/{cli,instance,config,install,skill,help}.rs` etc.); aproxy-format owns its tool/role messages under its own `src/i18n/`. Do not export product-specific catalogs from the contract crate just to make them visible to the binaries.

Invocation syntax (IDs are Rust items; these three reproduce `commands/restore.rs:28,35` and `commands/find.rs:67`):

```rust
message!(restore_empty(), en: "No instances to restore.", zh: "没有需要恢复的实例。");
message!(already_running(port: &str), en: "Port {port} is already running; skipping.", zh: "端口 {port} 已在运行，跳过。");
message!(find_count(n: usize), en_one: "Found {n} configuration:", en_other: "Found {n} configurations:", zh: "找到 {n} 个配置:");
```

Each expansion is a typed function taking `lang: Lang` before these arguments. A plain message returns `&'static str`; parameterized forms return `String`, matching existing allocating sites. For static arms use `const { format_args!(concat!($en)).as_str().unwrap() }` (likewise `zh`); for formatting use `format!(concat!($en), $($p = $p),+)` **in each arm**. `concat!` prevents implicit capture of unrelated locals; explicit named operands force use of every declared parameter in every language/form. Missing `zh:` has no macro arm. Count dispatch is `(En,1)`, `(En,_)`, `(Zh,_)`; zero uses the plural, no English suffix pasted onto Chinese. For multiple counts use independent complete-form decisions; retain original Chinese punctuation, newlines and rendered clap doc paragraphs, not the spelling of positional placeholders. Accept `&Path`/`Display` via a typed adapter at the edge rather than coercing IDs and sizes into opaque formatted English. Comments/docs for public items follow their crate. An owned error stores variants and typed arguments, not pre-rendered adjacent fragments; render on the chosen sink. For very hot or already nonallocating writes use the same checked arms with a formatter (`write!`) to avoid allocating formatted strings on success paths. No catalog or message lookup on the forwarding fast path.

A standalone `rustc --edition=2024` probe outside the repository rendered these three, checked counts 0/1/2, and rejected missing language (`unexpected end of macro invocation`), omitted parameter (`named argument never used`), and an undeclared capture (`there is no argument named …`). Step 2 should turn the negative cases into compile-fail doctests, including the plural arm. Per static call: one language match, no allocation; formatted call: one language match, normal Rust formatting and one owned result (possible growth), not formatting two strings. Size estimate **not a measurement**: roughly one extra UTF-8 English literal per previously Chinese-only definition (often 25–100 bytes) plus formatting code/alignment; tens of KiB of text across the CLI, potentially appreciably more with many distinct formatting shapes. Measure stripped release bytes of each binary at baseline vs each final variant, same target/toolchain/lockfile/profile/features; report byte deltas, number and total UTF-8 bytes of definitions, not the difference of unrelated debug executables. Also time a black-box loop of the plain/parameterized/count calls vs one-language formatting in release; subtract loop overhead and report iterations/allocations or known allocation paths. Do not claim the size or timings were measured here.

## 3. One choice per process, explicit choices per sink

1. `src/main.rs:35`: preserve the **sole** `-V`/`--version` raw-argv return before console setup, home lookup, settings, language, runtime or child creation. Mixed flags still go through clap. That's C5, not a translatable message. Bootstrap inspects `OsStr` arguments only to select the *settings-read policy*, never as a replacement argument parser. For `install|upgrade … --force` bypass settings even if the file is invalid/inaccessible (and when asking for help on that invocation). The existing validated force dispatch, lock and order are unchanged. Do not misinterpret `--download-proxy=…`, `--`, paths, or another command's `--force` as force install. A conservative no-settings probe is safer than reading a home the frozen installer never consults.
2. Normal CLI/format tools: first nonempty Unicode `APROXY_LANG` other than `system`, else valid absolute home via fallible `home::resolve_home()` and **only** the top-level `language` field in `settings.json`, else system UI, else English. No `home()` panic, settings mutation, last-good cache, warning/logging, recursive `Display`, runtime or validation side effect during bootstrap. Deserialize a tiny borrowed/owned serde struct ignoring unrelated keys, or inspect an object; missing/malformed/unreadable/non-string means skip. Honor existing settings vocabulary (`system` = skip, `en`, `zh-CN`); a malformed settings document remains an error later for commands that enforce it. Existing cached regular loads cannot override the initial choice. `--home` on format `try/check` is a sample execution base, not an instruction to load preferences from an inspected home.
3. Normalize tags with an ASCII case-insensitive `zh` prefix (including `zh_TW.UTF-8`); all other recognized input tags, including Unix `C`, `C.UTF-8`, `POSIX`, map to English. Unix: first usable `LC_ALL`, `LC_MESSAGES`, `LANG`, not `LANGUAGE` or `setlocale`. Windows: `GetUserPreferredUILanguages(MUI_LANGUAGE_NAME, &count, NULL, &units)` to size, then owned UTF-16 buffer of `units` including final NULs, call again; validate success/count/returned length, use **first** nonempty UI language name in preference order. Do not pick a lower-ranked Chinese item merely because one exists. Retry a changed size once on `ERROR_INSUFFICIENT_BUFFER`; no data, API failure, allocation/length/UTF-16 failure → English, silently. No `GetUserDefaultLocaleName`, console code page, region number or thread-global locale change. Reference: Microsoft Learn, *GetUserPreferredUILanguages (winnls.h)*, and locked windows-sys `Win32/Globalization/mod.rs` declaration. UTF-8 console setup is unrelated. A read-only probe of the actual Windows two-call API returned success on both calls, two entries in 13 UTF-16 units with a double terminator. That is a check of the API contract on one host, not a test of the proposed Rust resolver.
4. Publish once before building `cli::command_tree()`/`aproxy_format::run`'s human dispatch. Use a pure resolver over injected sources for tests. `current()` for a library linked without CLI initialization is English (no implicit settings read); an uninitialized read must **not** set the lock and preempt explicit initialization. `Display` on terminal-only typed errors uses `current()`; shared/serializable errors have an explicit `display_in(lang)`/machine projection and carry typed causes through `Result`, `io::Error` or anyhow chains until the final sink. Never `.to_string()` before choosing a sink just because an intermediate API currently takes `String`. No setting a global language back and forth, no thread-local toggling in async code.
5. Detached `__serve`, `__watchdog`, automatic install continuation, login restore, and format role **writers** always use explicit fixed rendering for logs/disk/wire; don't persist `Lang` or a starter's settings in a launch spec. Hidden workers do not look in an inherited unrelated home: dispatch with their explicit home as today, and do not read language preferences for machine-only work. Explicitly requested help for hidden commands is still human. Foreground `start` and an interactive installer can produce both kinds of output in one process. A desktop-launch failure is a human sink; a Tauri command DTO is not. Render a read-back failure using the *reader's* language; old/unrecognized fallback text is data. Don't translate or discard the underlying OS/library/third-party reason. Detached spawns can inherit `APROXY_LANG`; explicit fixed producers must remain fixed even so.

Everywhere: ignore unknown fields, use the received sanitized fallback for unknown/missing codes or unusable parameters, never translate by matching a sentence; never change its original code/exit on fallback. Do not forward render-only fields through blanket `to_value` into `--json` or the public desktop bridge. Use `default` + omit-if-absent only on approved optional additions.
