# W5：桌面界面接入真实数据

状态：设计（2026-11-19），没有开工，排在 alpha.4（format 一线）之后。依据：一次只读调研（2026-11-19），对照了
界面的 Backend 接口与原型（`aproxy-desktop/ui/src/lib/backend/`、`lib/types.ts`、`pages/`）、设计稿 §6 与 §9、现有的
IPC 客户端（`src/daemon.rs`）、只读枚举（`src/ops/enumerate.rs`）、操作层（`src/ops/`）与桌面外壳（`aproxy-desktop/src/lib.rs`）。
W5 的总体要求（窗口外观、主题、吉祥物、安全边界、构建与发布）见 [release-0.2.0](release-0.2.0.md) 的 W5 一节；本稿只管
「把演示数据换成真实数据」。

## 目标

界面不再显示演示数据，而是显示并操作这个 home 的真实实例：实例与状态、请求记录与详情、配置、设置、更新。标题栏的
「预览版 · 演示数据」标签随之消失。没有数据来源的功能不伪装：隐藏，或者明确写出数字的范围（例如「本次运行」）。

## 架构（定）

- **读的一侧放进 `aproxy-ipc`**：IPC 客户端（线上类型、帧与长度上限、对端核验）、事件流读取、只读枚举（记录的读取与
  身份核验、探测），以及不依赖 Tauri 的「home 视图」：跟踪实例的出现与消失（按 `(port, instance_id)` 区分每次运行）、
  每个活实例一条订阅、订阅时的快照与在途记录同翻页结果合并、`lagged` 与断线之后重取、有界的记录缓存，产出已经脱敏的
  DTO。主 crate 的 CLI 改用同一个客户端与枚举，只留一份实现。B6 当时为枚举开的「经注入」例外随之取消。
  理由：status、请求历史与事件流要认同一个运行身份、同一条安全边界、同一套重取算法，而且都能脱离 Tauri 测试。
- **写的一侧经注入**：`DesktopOps` 接口与过桥的 DTO 定义在 `aproxy-ipc` 的 `desktop` 特性后面（2026-11-22 改：原定放在
  `aproxy-desktop`，但 headless 的测试不链接它，实现就没法对着临时 home 测），主 crate 实现，`aproxy desktop` 启动时传进去：
  启动、停止、重启、强制停止、恢复；配置的读（脱敏投影）、校验与修改（与 `aproxy config set/unset` 同一条加锁写回）；
  settings 的读与改（只放行界面用到的键）；更新（拉起这个 home 的 `bin/aproxy install --check --json` 与
  `install --json`，把 NDJSON 事件转成界面事件）；界面自己的状态（`<home>/desktop/` 下：置顶与界面偏好）。
- **Tauri 命令窄而有类型**：snapshot、attach/detach、query_logs、request_detail、body_chunk 与各个写操作；一条按窗口的
  事件通道承载 Backend 的事件。不暴露通用的 `ipc(op, args)`，不给前端文件系统、shell 或网络权限；新命令同时登记进
  app manifest、生成的权限、唯一的 capability 与 invoke handler。
- **前端只做薄适配**：DTO 到界面类型、排序与展示、本地化。逻辑测试在 aproxy-ipc（Rust）与 TS 的 reducer 夹具里；
  aproxy-desktop 不放单元测试（RT-05）。

## 必须守住的约束

- 交给前端的只有脱敏后的投影，错误、事件、diff、复制出去的诊断文字都算。配置与 settings 的生效值里有明文密钥，
  解析与写回都在 Rust 侧做。请求记录里的 `user_agent`、`model` 等客户端给的字段不经过密钥替换，展示前要确认来源。
- 请求体只在用户点开详情时按块取，切换或关闭就取消；不预取，不常驻缓存。
- 写操作只认这个 home 解析出来的目标，执行时再核验身份；前端给的 pid、路径一律不作数。强制停止只对无响应的实例提供。
- 订阅：每个窗口对每个活实例至多一条长连接，各页面共用；`busy` 说明订阅已满，不说明实例卡死，此时退回轮询状态。
- 一个 home 一个窗口（现有的台账检查保留）；所有操作绑定同一个 home，包括现在读进程全局 home 的那几个操作。

## 原型功能的去留（定）

| 原型功能 | 0.2.0 怎么做 |
|---|---|
| 实例卡片、状态、启停与重启、强制停止、重连 | 做。状态按枚举的四种 liveness 与「等待恢复」；正常停掉的实例不再显示，不做「保存的实例档案」；「添加实例」从已发现的配置与别名里选 |
| 请求列表与详情、按块看体 | 做。多个实例合并显示，有界缓存与虚拟滚动；记录只在实例的内存里，实例重启后消失，界面不另存 |
| 置顶 | 做成书签：`<home>/desktop/` 存 request_id 与一份脱敏摘要，有条数上限；原记录被淘汰之后，详情显示「已不在实例的历史里」 |
| 救回统计 | 只显示有来源的数：每个实例本次运行的 `rescued_total`，最近一小时（快照的桶）。去掉「今日救回」：没有跨重启的日计数 |
| 长时间重试之后成功的庆祝 | 做。由新观察到的终态推导，首次加载与重连时不补放 |
| 配置编辑 | 常用键用结构化表单（base_url、listen_addr、只写的 api_key、proxy、头表、保活、超时），其余键只读并给出 `aproxy config set` 的写法；生效值与来源用 `config show --effective` 的同一份视图；保存之后列出要重启的实例，不自动重启 |
| settings | 看护者开关与界面偏好可改；`defaults` 等其余键只读 |
| 更新页 | 用 `install --check --json` 与 `install --json`；不显示版本说明（release notes 归 W7） |
| 主题字符串、内置吉祥物 | 保留，已经能用 |
| 关于与诊断 | 版本与变体取自本机二进制；主页链接用系统浏览器打开固定地址，或者去掉 |
| 原型的演示工具（`src/proto/`、场景与庆祝按钮） | 删除 |
| 开机自启 | 做（用户 2026-11-19 定）：三个平台各一种登记，见下面「开机自启」 |
| 扩展包、写操作授权、自定义吉祥物 | 做（用户 2026-11-19 定），见下面「扩展」 |

## 扩展（用户 2026-11-19 定：0.2.0 做）

用户的理由：用户自己往界面里注入代码是挡不住的（WebView2 的远程调试、替换前端资源都能做到），与其如此，不如官方
提供实现。官方实现要守住的只有一件事：别人做的扩展经官方渠道装进来时，默认拿多少权限。用户自己注入的代码不在
这套约束之内，这是有意的。方向（细节在 W5e 的设计里定）：

- 扩展包是 `<home>/desktop/extensions/` 下的一个文件夹加一份清单（id、名字、版本、种类、入口、要用的写权限）。种类
  先有三种：页面（导航里多一页）、吉祥物（现有的沙箱机制）、主题（现有的主题字符串）。
- 带脚本的扩展跑在沙箱 iframe 里（`sandbox="allow-scripts"`，不给 `allow-same-origin`），拿不到 Tauri 的 invoke，只能
  经 postMessage 调宿主界面提供的、有版本号的扩展 API。宿主按消息来自哪个 iframe 认出是哪个扩展，扩展自己报的身份
  不作数。原型那种「扩展与界面在同一个页面里」的做法不采用：同一个页面里的扩展能冒充界面直接调用一切，授权就成了摆设。
- 读不区分权限：扩展能看到界面能看到的（同样只有脱敏后的数据，请求体照样按需取）。
- 写操作（启停与重启实例、改配置、执行安装）由宿主带着扩展的身份交给 Rust；Rust 按 `<home>/desktop/` 里的授权记录检查，
  没有授权就发出确认请求，宿主在 iframe 之外弹确认框，扩展碰不到它，也伪造不了用户的回答。允许之后记住授权，可在
  设置里撤销；拒绝、关窗或超时都按拒绝处理。
- 吉祥物与页面扩展坏了只影响它自己的 iframe，界面照常。

## 开机自启（用户 2026-11-19 定：三个平台各做一种登记）

- 开关在设置页，打开时为这个 home 登记一项「登录后执行这个 home 的 `aproxy restore`」，关闭时删掉它；开关的状态以系统里
  实际登记的那一项为准（每次打开设置页都去读），不另存一份可能与系统不符的布尔值。登记的是 `<home>/bin/` 里的二进制
  与这个 home 的绝对路径；几个 home 各自登记，互不覆盖（登记项的名字带 home 路径的短哈希）。
- Windows：当前用户的 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 值，或任务计划程序里当前用户的登录触发任务，
  实现时选不闪窗口的那种：aproxy.exe 是控制台程序，直接登记会在登录时弹出控制台窗口，`aproxy desktop` 用的「分离出自身
  再退出」或无窗口的创建方式要实测。
- home 不经环境变量传（2026-11-22 改）：Windows 的 `Run` 值设不了环境变量，所以三个平台登记的都是同一条隐藏命令，
  home 的绝对路径作为参数；它做的事与 `aproxy restore` 相同，`restore` 本身不变。
- Linux：`~/.config/autostart/` 下的 XDG `.desktop` 文件（`Hidden=false`）。
- macOS：`~/Library/LaunchAgents/` 下的 LaunchAgent plist（`RunAtLoad`），用
  `launchctl` 装载与卸载。macOS 的发布构建还不在 0.2.0 的验证范围里，这一项按文档实现、在 CI 的 macOS 构建里编译通过即可，
  实测留给 macOS 进入范围之后。
- 失败（没有权限、登记项被别的程序删掉、二进制已不在）要在设置页说清楚，不能显示成已开启。

## 分段

- **W5a（Codex）**：把 IPC 客户端、事件流读取、只读枚举与 home 视图抽进 aproxy-ipc，CLI 改用它；测试在 aproxy-ipc。
- **W5b（Codex）**：`DesktopOps`、Tauri 命令与事件、capability、开机自启的三种登记；主 crate 实现并注入。DTO 的形状先写成
  文档，主代理审过再实现。形状文档是 [w5b-desktop-api](w5b-desktop-api.md)（2026-11-22 裁定，W5c 的前端照它写）。
- **W5c（主代理）**：前端的 Tauri Backend 实现，界面类型的调整（状态与阶段的词表、救回统计、置顶），去掉原型工具。
- **W5d（主代理）**：在真实应用里逐页过外观与交互，改文字与 i18n。
- **W5e（Codex 做 Rust 与宿主侧的协议，主代理做确认框与设置页）**：扩展包的清单与发现、沙箱 iframe 的宿主、扩展 API、
  Rust 侧的授权检查与记录。

## 留给实现时核对的

- 现在的 `ipc_read_in` 与订阅丢掉了对端返回的 pid：抽取客户端时把订阅绑定到核验过的那次运行。
- 订阅确认与事件的读取用的是不设上限的 `read_line`：抽取时补上与一问一答相同的长度上限。
- 配置写回在 Windows 上靠目录的 ACL 保护，`config::edit` 传的 `private` 是 false（settings 是 true）：home 之外的配置文件
  不受保护，界面写配置时要么同样提示，要么一并收紧。
