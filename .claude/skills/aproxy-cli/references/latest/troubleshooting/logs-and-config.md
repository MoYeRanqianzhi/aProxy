# Troubleshooting: logs, files and configuration

Part of [troubleshooting.md](../troubleshooting.md), which lists the other parts. Logs or files are missing or too large, or a config or settings file is rejected.

## Logs and files

| Symptom | Cause | Fix |
|---|---|---|
| Chinese text in a log looks garbled | The reading tool decodes the BOM-less UTF-8 file with the system code page; Windows PowerShell 5.1 `Get-Content` does this by default. aProxy sets the console to UTF-8 (65001) itself, so `chcp` is not needed | Use `aproxy logs <port>`, or `Get-Content -Encoding UTF8 <file>`, or PowerShell 7 |
| No log file for the port can be found | Log names are random and new at every start; they do not contain the port | `aproxy logs <port\|alias>` prints the path; never construct it from the port |
| A stopped instance's log is gone | Background cleanup (by a starting instance or the watchdog) deletes an unreferenced log once it has the built-in random name, is older than 10 minutes, and no instance or desired-state record refers to it. It never deletes custom `log_file` paths or `startup.log` | Copy logs you need before stopping, or set `log_file` |
| Stale `*.instance.json` records, `*.spec.json` handoff files or `*.tmp-*` files linger in `run/` | Cleanup only removes them once their writer is verifiably gone (temp and handoff files: no longer running or not found) and they are older than 10 minutes; read-only commands never delete them | Nothing to do. They disappear at the next instance start or watchdog scan; if they persist, check that the pid named in the file is really gone |
| `aproxy logs` says `该实例以前台模式运行（--foreground），日志输出在它的控制台，无日志文件可跟随。` ("this instance runs in the foreground; its log goes to its console") | Foreground instances have no log file | Read the console it runs in |
| `aproxy logs -f` never returns | `-f` follows the file until Ctrl+C or the instance stops | Run it with a timeout, or read the file at the printed path |
| The error preview reads `（二进制/压缩内容，共 N 字节，hex 前 48: …）` ("binary/compressed content, N bytes, first 48 bytes in hex") | The body is binary or could not be decoded (unknown encoding, corrupt data, over 8 MiB decoded) | Check the `content_encoding` field on the same line; `1f 8b` starts gzip, `28 b5 2f fd` starts zstd |
| `*.spooltmp` files remain in a `<home>/spool/<pid>-<hash>/` directory whose process is gone | Left by a crash or kill | They hold request and response bodies. The next instance that starts in this home, or the watchdog on its next scan, deletes them; with nothing running they can be deleted by hand |

## Configuration files

| Symptom | Cause | Fix |
|---|---|---|
| A command exits 3 with `[ERROR] settings.json 有错误:` and `[config_unknown_key]`, `[config_type]` or another code | settings.json is invalid: an old 0.1.x key, a misspelling, a wrong type or value, or a newer `schema`. Commands that need settings refuse to run on settings they could not read | For 0.1.x keys (`max_body_mb`, `forward_only`, `watchdog: true` and the like) run `aproxy migrate --dry-run`, then `aproxy migrate` (compatibility.md, "Converting the files with aproxy migrate"). Otherwise use the repair hints: `aproxy settings unset '<key>'` for each bad key, `aproxy settings set <key> <value>` to correct one, then `aproxy settings show`. Full policy: settings-json.md, "When settings.json is invalid" |
| `aproxy settings show` prints `settings.json 不是合法的 JSON 对象，只能手工修复（或删除它，回到内置默认）` ("not a valid JSON object; repair it by hand or delete it") and exits 3 | A JSON syntax error, or the file is not a JSON object; no command can merge or rewrite it | Fix the JSON at the reported line:column by hand, or, with the user's agreement, delete the file to return to the built-in defaults (aliases and global defaults go too). Never make a command "rewrite it with defaults": that would lose the aliases |
| `status` or `stop` prints `[WARN] settings.json 有错误` and then cannot find an alias | Those commands run on built-in defaults when settings.json is invalid; aliases live in the file and are unavailable | Address the instance by port or `all` now; repair the file with `aproxy settings` and the alias works again. A command that is not tolerated exits 3 instead |
| `aproxy settings set …` is refused with a message ending `set defaults.base_url first` (`[config_missing_key]`) | A credential in settings.json `defaults` has no target: `defaults.api_key` or a secret header without `defaults.base_url`, or a proxy password without `defaults.proxy` | Set the target first: `aproxy settings set defaults.base_url https://api.example.com`, then the key (settings-json.md, "Credentials in defaults follow their target") |
| An instance returns 401 after settings.json gained a global `api_key` | The instance's `base_url` does not name the same target as `defaults.base_url`, so the default key was withheld; `aproxy config show --effective` lists it under `全局默认里的这些凭据没有继承…` and warns with `default_credential_withheld` | Either point the instance at the same `base_url`, or give that instance its own `api_key` (config.toml or `aproxy config set api_key KEY`) |
| The instance will not start, and the error line ends with `[config_unknown_key]` | A misspelled key, an old 0.1.x name, or a key from a later release. config.toml is parsed strictly, so none of them is ignored | When the error list ends with ``Preview the 0.1.x changes with `aproxy migrate --dry-run`…`` (with or without a file name), or the key is a 0.1.x name such as `max_body_mb`, `forward_only` or `read_timeout_secs`, the file is from 0.1.x: convert it with `aproxy migrate` (compatibility.md, "Converting the files with aproxy migrate"). Otherwise fix the name or delete it with `aproxy config unset '<key path>'` |
| `aproxy config show` exits 3 | The config has error-level diagnostics; `show` still printed the values, then the diagnostics on stderr | Fix each `file:line:col: key: message [code]` line; config-toml.md, "Checks at start" explains the codes |
| A config change has no effect | Instances read their config only at start; and an instance started with `start` overrides keeps them across restarts | `aproxy restart <port\|alias>`; to drop a start override, stop the instance and start it without the flag |
| The user wants everything kept in memory, with no spool files | Disk cache is on by default | `disk_cache = false` in config.toml (or settings.json `defaults.disk_cache`), then restart |
| An instance's memory rose by tens of MB after some traffic and does not come down | The request history keeps recent request and response bodies in memory, up to `[history] body_budget_mb` (default 64) plus about 16 MiB of buffers | Expected. To shrink it, set `body_budget_mb` under `[history]` in config.toml (`0` keeps no bodies), or `aproxy settings set defaults.history.body_budget_mb <N>` for every instance, then restart |
