# 0.2.0 剩下的工作：交给 Codex 的任务清单

状态：进行中（2026-11-20 建）。这份清单是「谁在做什么、下一份任务书写什么」的唯一来源。总体计划与各工作流的要求在
[release-0.2.0](release-0.2.0.md)，协议与契约在 [w2-contracts](w2-contracts.md)，界面接入真实数据在
[w5-real-data](w5-real-data.md)，性能评估与优化在 [perf-0.2.0](perf-0.2.0.md)。

## 怎么协作

- 主代理是 leader：定方向、写任务书、审阅回执与审查结论、合并推送、打 tag、写给人看的文字与界面。实现、全量验证、看 CI、
  调研、审查、性能测量都交给 Codex（用户 2026-11-19、2026-11-20）。
- 任务书用英文，放在 `.agents/codex.local/<任务>.md`（不进版本管理），Codex 把回执写到 `<任务>.receipt.md`。一份任务书覆盖到
  下一个里程碑，按阶段写明范围、测试、提交与要过的命令。追加内容写成任务书顶部的 Revision。
- 任务的编号：`tNN` 实现，`vNN` 审查，`pNN` 性能，`rNN` 调研。
- 同一时刻只允许一个会话编译（本机可用内存约 2 到 4 GB）。审查与远程测量不编译，可以同实现并行。
- 每个实现阶段提交之后派一个独立的 Codex 会话审查（`codex exec review`，只读、不跑 cargo）。主代理对照设计稿裁定每条发现，
  成立的写进 Revision 交回实现方；设计稿没写明的地方先在设计稿里定下来再写 Revision。
- 性能测量在用户指定的服务器上做，用 gpt-6.2-sol（用户 2026-11-20 指定）；其余任务用默认模型。
